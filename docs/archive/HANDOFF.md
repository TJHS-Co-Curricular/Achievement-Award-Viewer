## 3. 关键决定（为什么选 A 不选 B）

| 决定 | 原因 |
|---|---|
| 规则写在 `config/*.json`，不写死在代码里 | 规则经常由上级改；维护者不是程序员，改 JSON 就能生效，exe 也不用重新打包（exe 旁边的 `config\` 优先采用）。 |
| Flask 本地网站 + PyInstaller 单一 exe | 老师双击就能用，电脑上不用装 Python；同一个网站也能开局域网共享。 |
| 浏览器端用 `core.js` 重算，不再请求服务器 | 手动「计入 / 不计」之后数字要马上变。复杂判断由 Python 预先算好放进每个 block（`b.rc / b.ex / b.aw / b.hr / b.sp / b.mv / b.nk / b.wk / b.wr / b.sc`），JS 只负责套用手动调整再加总。 |
| 服务时数优先用学生自填的总数，不用逐项相加 | 上级 2026-09-24 定：只用逐项相加，对没有逐项写时数的学生不公平。 |
| 没写正 / 副的职位当「正」（做法 A） | 上级 2026-09-24 校对时定的。 |
| 资料总览：工作 = 服务栏条数，活动 = 比赛和服务以外的栏目一律算 | 维护者 2026-09-28 定（v1.4.0）。之前例常、同一类合并、营员、参与者等条件太复杂，全部取消。 |
| 「服务（数量）」另外一栏处理例常和重复 | v1.5.0。把「工作」保持简单（每条都算），去重、扣例常放在新栏位，两者互不影响。 |
| 小组里只有组长算中层管理，其他一律算会员 | 上级 2026-09-28 改定（v1.5.1），取代先前「组员不计」「礼仪小组组员 = 中层管理」。 |
| 资料总览只显示，不能在网页里改 | 维护者定：评审、顾问建议两栏在 Google 表格里自己填。 |
| 年份栏自动（最新年份 = 高三，往前推） | 维护者定：每届不用手动改设定。 |
| `Result/ data/ output/ logs/` 和 exe 不进 git | 学生个人资料；exe 太大（约 35 MB）。 |
| 版本号只在 `achievement/__init__.py` 改 | 网页、启动画面、`/api/version`、日志都从这里读；测试会检查 CHANGELOG 有没有同步。 |

## 4. 已知问题

1. **「参与奖」会被算成获奖。** 规则文档写「参与奖不算」，但 `award.json`「一、不算获奖」的清单里没有「参与奖」。
   所以「XX比赛——参与奖」会因为后段有「奖」而算获奖，「获得参与奖」会因为第四条规则而算获奖。2026-10-16 实测确认。
   三届资料里目前没有这种写法，现在的数字不受影响。没有测试覆盖这一条。
2. **显示问题，不影响计分。** `rules.clean_role` 会删掉「联课活动」四个字，所以「2023/2024联课活动处工委」显示成「执委(处工委)」。
   ★ 标记和职务数都正确。影响 2025 届 C08 刘芯彤（2023、2024 两年）。
3. **资料问题。** `B08 C04 21806 蔡佳芯` 的舞蹈团职位被读进 B08（培训队）那一格，整格不计，要人工看原件。
4. **award.json 的「gold」是只看有没有这几个字母。** 比赛名称里有 Gold（例「Gold Star Music Festival」）也会算获奖。三届资料里所有含 gold 的条目实际都有得奖，暂时没有误判，只是要留意。
5. **踩过的坑：**
   - `templates/*.html` 不要用 Prettier 等格式化工具整理，会弄坏 Jinja 的 `{{ }}`。
   - `scripts\*.bat` 必须纯 ASCII + CRLF 换行，不然 Windows cmd 会出错。
   - 「26.5小时」曾被当成编号读成 5 小时（已修，`rules.strip_num`）；「1.18小时」开头的「1.」是编号。
   - 总服务时数一格里同一个数字重复写只算一次（何伟琦 2026：336 → 168 h）。
   - Championship、Medalist、Kejohanan 只是比赛名称，不是获奖（已用正则排除）。
   - 康熙部首「⼈」「⼯」长得像「人」「工」，要自动换回来。
   - 改 `parse_rows` 很容易影响很多人：每次改完都要用三届资料比对改动前后的差异。
6. **文档过时的地方：**
   - `Docs/成就奖计分规则.md` 开头写「适用版本 v1.3.4」，应该是 v1.5.1。
   - 同一份文档第八节的编号从 3 直接跳到 5。
   - `Docs/高三最高成就奖-成就奖计分规则.docx` 是旧版，没有跟着更新。
   - 决定记录里还留着「上级回复：营员算活动」「只是参与者不算工作」，但 v1.4.0 已经取消这些条件（见 §7-1）。
7. `参考数据交接.md` 提到的 `Docs\generated\` 旧产出（已知职位一览、已知获奖一览、规则更新对照）已经不在了。需要时用 `--list-roles` / `--list-awards` 重新产生。
